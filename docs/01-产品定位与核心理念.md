# 01 - 产品定位与核心理念

> 权威文档：产品定位。其他文档引用本文，不重复定义。

## 1. 一句话定位

**Linkbase 是面向研发团队的 Notion**——一个以页面为中心的协作知识库。它首先是一个极好用的文档工具：注册、落笔、写作，没有任何前置仪式；在此之上，通过**扩展节点**与**页面模板**把研发场景（PRD、技术设计、API、测试、AI 辅助）逐块叠加进来。

## 2. 与 docmost 的关系（功能基线）

基本功能**对标 docmost 开源版**（开源的 Notion/Confluence 替代品）：

- **对齐**：编辑器能力（Tiptap 系写作主路径）、页面树与回收站、全文搜索、收藏/标签、版本历史、评论、Markdown 导入导出、实时协作、暗色模式、i18n——即 04 的 P0/P1 清单；
- **不搬**：只对齐功能与交互形态，不采用其实现栈（NestJS/Fastify/Mantine/Kysely/Hocuspocus/socket.io 均不引入，技术基线见 README）；后端保持 Hono on Bun，前端保持 React + shadcn/ui；
- **不做**：其 Space/空间层级与空间级权限、页面级权限（02 §1.1、03 §4）；
- **差异点**：Base（数据库，P1）是超出 docmost 开源版的差异化能力；研发特化扩展（API 块、Mock、AI）是本产品的长期方向（P2+）。

## 3. 核心理念

### 3.1 打开即写，零仪式

注册成功即自动拥有一个工作空间（无感，可随时改名）；首屏直接是一篇可编辑的《快速开始》页面，光标已在正文闪烁；组织方式由用户自己长出来：子页面、标签、收藏，而不是系统预设的容器。

**任何功能都不得强迫用户先建容器再建内容。**

### 3.2 一切内容皆页面

页面是唯一的内容容器，页面内部是一棵 ProseMirror 文档树（Tiptap，见 05）。由此推出一组硬规则：

| 规则 | 含义 |
|------|------|
| 一切内容皆页面 | PRD、技术设计、会议纪要、API 文档——都是页面，只是模板与节点组织不同 |
| 一切结构皆节点 | 表格、Callout、公式、图片、子页面——都是文档树上的节点（Tiptap 扩展） |
| 引用优于复制 | 页面间引用使用页面引用节点，被引用处自动形成反向链接（P2） |
| 内容即 Y.Doc | 每个页面是一个 Yjs 文档；服务端存储增量 updates 与快照，没有内容关系表 |
| 研发能力是扩展节点 | 后期的 API 块、Mock 块、测试用例块都是普通自定义节点，不是独立子系统 |

### 3.3 协作是一等公民

内容真相自始至终是 CRDT（Yjs，05 §3），多人实时协作、离线编辑、历史版本都不是「后期插件」，而是存储模型自带的属性。MVP 先跑单人编辑 + 多端同步，实时多人随 Phase 2 打开。

### 3.4 AI 作用于页面上下文

AI 能力（Phase 3+）以页面为单位消费与产出：选中文字改写、基于整页生成测试计划、PRD 生成技术设计草稿。AI 产物一律以**草稿/草稿页面**落盘，人工确认后生效。

## 4. 产品原则（写代码前先过一遍）

1. **快**：编辑器本地操作零网络等待，同步在后台进行；首屏 < 1.5s。
2. **简**：UI 只保留一个主操作入口（新建页面），其余能力通过 `/`（slash）与 `⌘K` 涌现。
3. **稳**：数据不丢——每次编辑生成 Yjs update，先本地后服务端，断网可继续写。
4. **美**：界面完整对标 Notion 的克制与精致（见 06），细节不将就。
