# 02 - 核心模型：工作区与页面

> 权威文档：领域模型与实体规则。表结构见 08，API 见 10，编辑器与内容节点见 05。

## 1. 两级实体，仅此而已

```
Workspace（工作空间）
   └── Page（页面）× N          ← 树状，通过「子页面节点」无限嵌套
          └── 内容节点 × N      ← 一棵 ProseMirror 文档树（Tiptap），存于页面 Y.Doc，不是数据库实体
```

数据库中真正存在的实体只有：**User、Workspace、Page、Blob（附件）、Tag**。其余一切都是页面内的内容节点，或者页面上的元数据。

### 1.1 Workspace

- 注册时**自动创建**默认工作空间并设为 Owner，无感（对应 01「零仪式」）。
- 是成员与权限的边界（见 03），也是页面的顶层命名空间。
- 用户可创建多个工作空间并切换；MVP 支持创建/改名/邀请成员。
- **不引入 Space/空间层级**（docmost 有 Space 与空间级权限，本产品明确不做，见 03 §4）：工作空间即最大容器，页面树直接铺开。

### 1.2 Page

- **唯一的内容容器**。一个页面 = 一份 ProseMirror 文档（Tiptap 渲染，05 §3）= 一个 Y.Doc。
- 页面树：页面内插入「子页面节点」（subpage 节点，05 §2）即形成父子关系；父页面删除进回收站时提示子页面去向（见 §4）。
- 每个页面在数据库只有一行元数据（id、标题、图标、是否在回收站等）；**正文内容不在行里，在 Y.Doc 里**（updates + 快照，见 08 §4）。标题是独立列，客户端直写（05 §5）。
- 单一文档模式（无白板）：页面只有一种富文档形态，不做画布/白板模式。

### 1.3 内容节点

- 内容节点由 `packages/editor` 的 Tiptap 扩展定义与管理（05 §2.1 清单），前端编辑态与服务端提取共享同一套 schema 命名（05 §4），**服务端不理解内容语义，只做结构化提取**。
- 应用层只关心两类节点行为：
  - **子页面节点（subpage）**：影响页面树，服务端需提取（派生缓存 parent_id，08 §5）；
  - **页面引用**：页面间引用的载体（P1 mention 扩展支持页面引用），是「引用优于复制」的实现，反向链接由它推导（P2）。

## 2. 组织方式：不用容器，用涌现

结构是长出来的，不是先建好的：

| 手段 | 说明 | 优先级 |
|------|------|--------|
| 页面树 | 侧边栏树 + 子页面节点，支持拖拽排序/换父 | P0 |
| 标签 Tag | 工作空间级标签，可给页面打多个；侧边栏按标签聚合视图 | P0 |
| 收藏 Favorites | 侧边栏置顶快捷入口 | P0 |
| 最近访问 Recent | 按访问时间自动记录 | P1 |
| 评论 Comments | 页面级 + 行内评论 | P1 |
| Base（数据库） | 一种页面内容形态：行 + 类型化属性 + 视图（表格/看板），行可挂子页面——「项目」「需求池」用它实现。数据完全存于页面 Y.Doc，**无需任何新表** | **P1** |

**「项目」「需求」不建实体**：一个项目 = 一个父页面 + 一个标签（或一个 Base 视图）；一篇 PRD = 用 PRD 模板新建的页面。页面间关系一律由页面引用承载。

### 2.1 Base（数据库，P1）

- 定位：对齐 Notion Database / docmost Base 的**页面内容形态**——可整页是一篇 Base，也可在普通页面内插入 Base 节点；
- 组成：行（每行可关联/新建为子页面）+ 类型化属性（文本/选择/日期/人员等）+ 视图（表格、看板按选择列分组；筛选/排序进阶 P2）；
- 存储：数据存于所在页面的 Y.Doc，不新建数据库表（表结构见 08 §8 待细化）；
- P0 不做（04 §2）：Tiptap 无现成数据表格组件，完全自研，MVP 后置。

## 3. 模板系统

模板 = 预置的文档内容快照（ProseMirror JSON，随页面 Y.Doc 存储见 08 §4），存为特殊页面（`pages.is_template = true`），用户「新建 → 从模板」时把快照复制为新页面。

| 模板 | 内容 | 优先级 |
|------|------|--------|
| 快速开始 | 默认首屏页面，自带引导内容 | P0（注册自动创建） |
| 空白页 | 无内容 | P0 |
| 会议纪要 | 标题/日期/参会人/议题/决议/待办 | P1 |
| PRD | 背景/目标/用户故事/功能范围/验收标准(GWT)/风险 | P1 |
| 技术设计 | 背景与目标/方案选型/架构图/接口设计/数据结构/风险 | P1 |
| 周报 | 本周进展/数据/下周计划 | P2 |

研发模板中的结构（如验收标准的 Given/When/Then）只是**约定俗成的节点组织**，不是数据库结构；后期需要结构化消费时（如生成测试计划）再由 AI/解析器从文档读取。

## 4. 生命周期

### 4.1 页面

```
正常 ──删除──▶ 回收站（is_trash=true，Y.Doc 保留）──恢复──▶ 正常
                    │
                    └──彻底删除（30 天后自动，或手动）──▶ 物理删除（含 updates/快照/附件引用检查）
```

- 回收站内页面不出现在树、搜索、标签视图中。
- 删除父页面：子页面一并进回收站（父子关系由子页面节点承载，随内容一起保留）；恢复时整棵恢复。

### 4.2 工作空间

- 删除工作空间 = Owner 二次确认 + 全量物理删除（MVP 暂不做，仅支持离开/转让，降低误删风险）。

## 5. 命名与 ID

| 项 | 规则 |
|----|------|
| 用户可见 ID | 无。页面没有 PRD-102 这类业务编号，靠标题 + 路径 + 搜索定位（URL 即 `/:workspaceId/page/:pageId`，见 06 §2） |
| 内部 ID | UUID v7（时间有序，利索引），由服务端生成；需要稳定标识的节点（subpage 的 pageId、评论锚点 nodeId 等）由客户端生成 nanoid |
| 标题 | 无标题页面显示 `无标题`；`pages.title` 列为唯一真相，客户端经 PATCH 即时写入（05 §5），不参与搜索索引之外的派生 |

## 6. 待细化

- 页面引用的反向链接面板（backlinks）的数据来源与查询方式（倾向服务端从内容提取引用表，P2 立项时定）。
- 页面树拖拽跨工作空间移动（move）是否支持（倾向不支持 MVP）。
- 模板的版本升级策略（模板更新后已建页面是否受影响——倾向不受影响，模板仅出生时复制）。
- Base 行与子页面的绑定细节（行升级为子页面 vs 链接已有页面）、行数据的 Y.Doc 结构（Y.Map 行集 vs 每行子文档）——P1 实施时定。
- Base 内嵌于普通页面时的 `parent_id` 语义（Base 行转子页面时父页指向谁）——P1 定。
