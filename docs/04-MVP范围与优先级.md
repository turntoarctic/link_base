# 04 - MVP 范围与优先级

> 权威文档：功能范围与验收标准。进度状态一律见 91，本文不维护状态。编辑器能力明细见 05 §2.1。

## 1. MVP 目标

**一个人 + 一个小团队，把 Linkbase 当 Notion/docmost 用**：注册即写、页面树组织、编辑流畅、多端同步不丢字、能搜索、能贴图、能打标签。功能基线对标 docmost 开源版的**日常写作主路径**（编辑器、页面管理、搜索、回收站），实时多人协作是第一个里程碑后的下一站，不在 MVP 内。

## 2. P0（MVP，Phase 0–1 完成）

| # | 功能 | 验收标准 |
|---|------|----------|
| P0-1 | 注册 / 登录 / 登出 | 邮箱+密码；Access Token 15min + Refresh 7d；刷新无感 |
| P0-2 | 零仪式首屏 | 注册后直接进入自动创建的工作空间与《快速开始》页面，光标可立即输入 |
| P0-3 | Tiptap 编辑器核心写作集 | 段落/标题/有序无序列表/待办/引用/代码块（语言高亮）/分割线/行内代码/粗斜删/链接/高亮；表格（行列增删、表头）；Callout；`/` slash 菜单；Markdown 快捷输入（`# `、`- `、``` 等）与 Markdown 粘贴转富文本；块拖拽手柄；选中浮动工具条；undo/redo |
| P0-4 | 页面 CRUD 与页面树 | 新建/重命名/删除入回收站/恢复；侧边栏树展示；子页面节点建页；树内拖拽换序换父 |
| P0-5 | 内容同步（单人多端） | 编辑产生的 Yjs update 推送到服务端落库（05 §3.2）；本地 y-indexeddb 缓存秒开；换设备/浏览器打开同一页面内容一致 |
| P0-6 | 回收站 | 列表、恢复、彻底删除、30 天自动清理任务 |
| P0-7 | 标签 | 增删改、给页面打标签、侧边栏标签聚合视图 |
| P0-8 | 收藏 | 收藏/取消，侧边栏置顶区 |
| P0-9 | 图片上传 | 拖拽/粘贴/工具条上传（10 §5.3），块内展示、上传中占位、失败重试 |
| P0-10 | 搜索 | 按标题 + 正文关键词搜索页面，结果含路径面包屑 |
| P0-11 | ⌘K 命令面板 | 快速跳页、新建页面、搜索三合一 |
| P0-12 | 暗色模式 | 亮/暗/跟随系统三态切换，全站一致（含编辑器） |
| P0-13 | 国际化基础 | i18next 框架（zh-CN 默认）；**全部 app chrome 与编辑器 UI 文案走 i18n**，禁止硬编码；API 错误按 code 本地化；语言切换（设置 + 登录页）并持久化（13） |
| P0-14 | 单机部署 | `docker compose up -d` 一条命令拉起全栈 |

## 5. 非功能验收（P0 期）

| 指标 | 目标 |
|------|------|
| 首屏可交互（已有会话） | < 1.5s（本地网络；y-indexeddb 缓存命中时内容即时呈现） |
| 输入延迟 | 感知为零（本地编辑，不等待网络；同步后台进行） |
| 同步可靠性 | 断网继续编辑，恢复后自动补推，无内容丢失（e2e 用例覆盖） |
| API P95（除搜索） | < 200ms |
| 搜索 | < 500ms（万页级数据集） |
| Docker 冷启动 | < 60s 全部健康 |

## 6. 明确不做（MVP 及远期边界）

- **Space/空间层级与空间级权限、页面级权限、访客角色**（docmost 有，本产品不引入，模型见 02 §1.1、权限见 03 §4）；
- **白板/画布模式**（Edgeless 类）——单一富文档定位；
- 项目/需求实体（不建实体，见 02 §2）；
- 离线 PWA 与移动端 App（响应式 Web 够用即可；y-indexeddb 缓存只服务多端一致，不承诺离线完整功能）；
- 多实例水平扩展（单机 docker compose；架构上不留单例假设的死锁——WS 广播如需扩展走 Redis pub/sub，见 09 §7）；
- Figma 专属集成（通用 Embed 覆盖网页级嵌入，P2）、Webhook、开放 API；
- 计费与多租户配额。

## 7. 验收方式

每个 P0 项在 90-执行计划 中对应任务与验收用例；e2e 用 Playwright 覆盖 P0-2/4/5/6/10/13 的主路径（沿用现有 e2e 基建）。

## 8. 待细化

- 回收站 30 天自动清理的调度实现（倾向 server 内置定时任务，Phase 1 定）。
- PDF 等文件附件进 P1 的预览深度（仅下载 vs 内嵌预览，P1 实施时定）。
- 评论解决（resolve）的流转规则（P1 实施时定）。
