# 05 - 编辑器集成设计（Tiptap）

> 权威文档：编辑器选型、扩展体系、Y.Doc 存储链路、服务端元数据提取。存储见 08，协作见 09，API 见 10。

## 1. 技术选型

| 项 | 选型 |
|----|------|
| 编辑器框架 | **Tiptap v3**（ProseMirror 6 之上），npm 安装最新稳定版（3.x），无 vendor、无版本特例 |
| React 绑定 | `@tiptap/react`（`useEditor` + `EditorContent`） |
| 基础扩展 | `@tiptap/starter-kit`（段落/标题/粗斜删/行内代码/列表/引用/代码块/分割线/undo-redo 等） |
| 协作绑定 | `@tiptap/extension-collaboration`（内部即 y-prosemirror），**P0 即装**（§3） |
| 自研扩展包 | `packages/editor`（workspace 本地包，§2），组织方式对标 docmost 的 `packages/editor-ext` |
| Markdown | `@tiptap/markdown`（粘贴/序列化）；若能力或许可不满足，在包内以 marked 自研转换层（docmost 同款做法，§9） |
| 代码高亮 | `lowlight`（代码块按语言高亮） |
| 本地缓存 | `y-indexeddb`（页面内容本地持久化，秒开与断网兜底，§3.1） |

选型理由：

- **功能基线对齐**：docmost（本次功能对标的开源产品）的编辑器即 Tiptap v3 + 自研扩展包，表格/代码高亮/协作光标/Markdown 等能力与其开源功能一一对应；
- **React 原生**：编辑器是普通 React 组件树的一部分，无 Web Component、无框架桥接层；菜单/弹层等编辑器 UI 直接用 shadcn 体系（06 §5）；
- **按需组合**：starter-kit + 每个能力一个扩展，不背整框架；自研扩展就是标准 ProseMirror Node/Mark + NodeView，工程边界清晰；
- **存储不变**：内容真相仍是 **Y.Doc**（08 §4），Tiptap 经 y-prosemirror 双向绑定 PM 文档，08/09 的存储与协作设计全部延续。

依赖红线：**yjs 单实例**。`@tiptap/extension-collaboration`、`y-prosemirror`、服务端 `packages/ydoc` 与前端一切直接依赖的 `yjs` 必须同为 `^13` 最新；Bun `overrides` 钉死，合并前 `bun pm ls yjs` 校验——双实例 = CRDT 分裂，全项目最高红线（06 §1.1）。

## 3. 内容存储链路：ProseMirror ↔ Y.Doc

编辑态是 ProseMirror 文档；**内容真相是 Y.Doc**（08 §4）。`@tiptap/extension-collaboration` 经 y-prosemirror 把两者双向绑定：PM 文档的每次 transaction 产出 Yjs update，Y.Doc 的远程变更自动回放进编辑器。**每个页面一个 Y.Doc**。

### 3.1 页面打开（多端一致 + 即时呈现）

```ts
// apps/web/src/features/editor/open-page.ts（设计草图）
import * as Y from 'yjs';
import { IndexeddbPersistence } from 'y-indexeddb';

export async function openPageDoc(pageId: string): Promise<Y.Doc> {
  const ydoc = new Y.Doc();
  const local = new IndexeddbPersistence(`page:${pageId}`, ydoc); // 本地缓存
  await local.whenSynced;                                         // 先渲染本地状态，秒开

  const sv = Y.encodeStateVector(ydoc);
  const res = await fetch(`/api/workspaces/${wsId}/pages/${pageId}/doc?state=${toBase64(sv)}`);
  if (res.status === 404) {                 // LB_PAGE_NOT_FOUND：服务端无内容
    if (!hasContent(ydoc)) initEmptyDoc(ydoc); // 本地也为空 → 新页面，初始化空段落
    return ydoc;                            // 新建页场景：本地为准
  }
  const missing = new Uint8Array(await res.arrayBuffer());
  Y.applyUpdate(ydoc, missing);             // 服务端差异合入（08 §4.1）
  return ydoc;
}
```

要点：

- **本地缓存先行**：y-indexeddb 保证二次打开零网络等待；首次打开为空文档，pull 完成后渲染（页面级 loading 承担骨架屏）；
- `404 = 服务端无此页内容` → 本地为准（新建页场景，错误码语义见 10 §6）；
- 服务端 pull 返回的是差异 update（快照快路径或合并差分，08 §4.1），客户端不感知区别。

### 3.2 保存（客户端 → 服务端）

- 监听 `ydoc.on('update', ...)`：**只推送本地产生的 update**（`updateOrigin` 非远程回放），去抖 500ms 批量合并后 `POST /pages/:pageId/doc`（octet-stream，10 §5.2）；写路径语义见 08 §4.2（服务端只落库不解析）；
- push 4xx（非 401/429）时告警——内容被拒按 bug 处理；401 交给全局 fetch 拦截器刷新重放（06 §4）；
- 断网：待推队列在内存，恢复后补推；y-indexeddb 已持久，刷新页面不丢。

### 3.3 跨标签页（P0，小 provider）

同一浏览器多标签页编辑同一页面：一个 ~50 行的 BroadcastChannel provider 在标签页间转发本地 update（与 awareness，P1）——不必等 P1 的 WebSocket。P1 接入 WS provider（09 §6）后，它退化为离线兜底。

### 3.4 实时协作（P1，启用 09）

协作扩展体系不变，只加两件事：

1. **WS provider**：连接 09 的房间，y-protocols 编码收发 sync/awareness 帧；
2. `@tiptap/extension-collaboration-caret`：协作光标/选区/姓名标签（对齐 docmost 的协作体验）。

客户端接入细节见 09 §6。

## 4. 服务端元数据提取（packages/ydoc）

`pages.parent_id`、`pages.text` 是 **Y.Doc 的派生缓存**（08 §5）。提取在服务端完成；`packages/ydoc` 只依赖 `yjs` + `y-prosemirror` + `@linkbase/editor/server`（命名常量），**零 DOM、零 React、零 ProseMirror 编辑器运行时**：

```
Y.Doc（合并完成） ──yDocToProseMirrorJSON──▶ ProseMirror JSON ──遍历──▶ { text, subpageIds }
```

- 触发：快照合并任务完成后（08 §4.3），以及 doc push 后的异步对齐（不阻塞写路径）；
- `text`：按文档序深度优先拼接全部文本节点，供搜索（08 §6）；
- `subpageIds`：subpage 节点的 `pageId` 属性 → 第一个为 `parent_id`；发现多个子页引用指向同一子页时取第一个并告警（08 §5）；
- **标题不在提取范围**：标题是独立列，客户端直写（§5）；
- 单测交叉验证：客户端用 Tiptap headless 按 schema 生成真值文档，提取器读取比对 text/subpageIds 一致。

## 5. 标题与页面骨架

- **标题是编辑器上方的独立输入框**（React 受控组件，Notion/docmost 同款形态），不是编辑器内节点：`pages.title` 列为唯一真相，输入去抖后 `PATCH /pages/:pageId`（10 §4）；08 §3.3 已按此定义（title 不再从内容提取）；
- 新页面：服务端建行（title 可空）→ 客户端打开时渲染空文档与标题占位（显示「无标题」，02 §5）；
- 路由不变：`/:workspaceId/page/:pageId`（06 §2）。

| 交互 | 实现 |

| Markdown 粘贴 | 剪贴板 text/markdown → 解析为 PM 文档插入 |

## 7. 模板与导入导出（P1）

- **模板建页**（02 §3）：模板页本身是普通页面（`is_template`）；从模板建页 = 服务端复制模板当前快照为新页（08 §4.4，不变）；
- **Markdown 导出**：服务端 `packages/ydoc` 取合并态 → PM JSON → Markdown 序列化下载；
- **Markdown 导入**：服务端解析（md → PM JSON → 构建 Y.Doc），大文档不吃客户端内存；实现路径见 §9 待细化；
- 模板内置内容随应用发布（seed），不在运行时从远程拉。

## 8. 扩展块路线（P2+，概要）

自研扩展 = 标准 ProseMirror Node（视图用 React NodeView 渲染，`ReactNodeViewRenderer`）：

1. **API 块**：method/path/参数表/响应示例的结构化节点，attrs 存 JSON，NodeView 自绘；
2. **Mock 块 / 测试用例块**：依赖 API 块，P2/P3 按需立项，届时新立文档；
3. 所有扩展都在 `packages/editor` 内开发，**不改 Tiptap 上游源码**；需要覆盖上游行为时用 ProseMirror plugin 扩展点解决。
