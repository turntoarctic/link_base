# 90 - 执行计划

> 权威文档：阶段划分与任务分解。**本文不维护状态**——状态一律见 91。每个任务的验收标准是完成的唯一定义，不写逐步 bash 脚本，代码细节以设计文档为准。

## Phase 0：模型改造与技术验证（约 1 周）

目标：搭好 Tiptap 数据通路，跑通「注册 → 建页 → 写字 → 服务端落库 → 换端打开」的最小闭环。

| 任务 | 内容 | 验收标准 |
|------|------|----------|
| T0.1 拆除旧模块 | 删除不再需要的旧代码与路由、旧表（见 91 §2 拆除清单） | typecheck/test 全绿，无残留引用 |
| T0.2 编辑器基座 | 引入 Tiptap v3（@tiptap/react + starter-kit，05 §1）+ 落地 `packages/editor` 骨架（05 §2）：schema 常量、createEditor 装配、server 子路径 | `bun install`/typecheck 绿；编辑器组件可渲染空文档；`bun pm ls yjs` 无重复 |
| T0.3 数据库重建 | 按 08 建 drizzle schema + 迁移（含 `CREATE EXTENSION pg_trgm`） | `bun run db:migrate` 全表与扩展建成；seed 能建空间+快速开始页 |
| T0.4 元数据提取重做 | `packages/ydoc` 改为 yjs → yDocToProseMirrorJSON → text/subpageIds（05 §4）；客户端 Tiptap headless 生成真值交叉验证 | 服务端能从 update 提取纯文本/子页 id（title 为独立列不提取），单测覆盖 |
| T0.5 doc 通路 | 10 §5.2 两个二进制端点 + yjs merge/diff 工具（07 lib） | 接口测试：push 随机 update 后 pull（带旧 state vector）能取回差异；空页 404 |
| T0.6 页面 API | 10 §4 页面 CRUD + 回收站端点（含 title PATCH 直写） | register→create page→edit title→trash→restore 全链接口测试通过 |
| T0.7 认证全流程与零仪式首屏 | 注册/登录/刷新/登出闭环（07 §5、10 §2）+ 注册后自动建空间与快速开始页并直接进编辑器（01 §3.1） | P0-1/P0-2：token 刷新无感；新用户注册后无任何建容器步骤即可输入 |
| T0.8 i18n 基础设施 | i18next 接入 + zh-CN/en 资源骨架（命名空间 common/auth/workspace/editor/errors）+ 错误码映射 + 守护脚本（无硬编码/key 对齐，13 §7） | P0-13：登录页双语可切换并持久化；登录后文案随 `users.locale`；脚本全绿 |
